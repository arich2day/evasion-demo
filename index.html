Last Mile Reassembly & Malicious File Delivery

Modern attackers smuggle files past Secure Web Gateways by reassembling them inside the browser, after traffic has already cleared network inspection. These 8 modules use benign EICAR / Palo Alto Wildfire test payloads to check whether your stack catches client-side reassembly.

Test 1: Web-Worker Malware Chunking

The browser spawns a hidden background process (Web Worker) to pull data in chunks from the network. Reassembly happens completely off the main thread, bypassing legacy DOM-only inspection tools.

Test 2: Basic File Smuggling Attack

A Base64 string representing a PE file is passed to a hidden background Web Worker. The worker decodes the payload deep in browser memory and returns the executable binary back to the main thread for execution.

Test 3: Runtime-Assembly via Polymorphic JavaScript

A dynamic engine generates a completely unique, randomized script signature every time you click the button. It drops the payload and executes a simulated C2 beacon, demonstrating an active payload bypassing static network filters.

Test 4: Quishing Attacks - The Airgap Jump

Adversaries embed malicious QR codes into legitimate websites. The attack begins on a corporate device, but shifts execution to an unmanaged mobile device during the scan.

Test 5: Advanced HTML Smuggling (SVG Embedded Payload)

Instead of storing the payload in a JavaScript variable, the attacker embeds the malicious Base64 code within the metadata of an invisible vector image (SVG) injected into the DOM. The script later extracts the payload from the image properties, completely bypassing gateway scanners.

View DOM Smuggling Logic
// Payload hidden inside an innocuous SVG tag property const svg = document.createElementNS('http://www.w3.org/2000/svg', 'svg'); svg.setAttribute('data-malware-payload', b64_payload); document.body.appendChild(svg); // Later, script extracts and drops the file const extracted = document.querySelector('svg').getAttribute('data-malware-payload'); triggerDownload(atob(extracted));

Test 6: Browser-Based Crypto-Jacking (Resource Hijacking)

Malicious JavaScript execution does not always result in a file download. Attackers use hidden iframes or Web Workers to silently hijack the victim's CPU resources to mine cryptocurrency, degrading machine performance and costing the enterprise electricity and productivity.

Pro Tip: Open your machine's Task Manager / Activity Monitor before clicking Run to see the CPU spike!

Test 7: Web Socket + Malware

Network layer security can't inspect WebSocket connections because they're encrypted. Therefore, these solutions are completely blind to threats transmitted through these persistent connections.

The browser sends an HTTP request to the server, and the server responds with a Status Code 101 (Switching Protocols), upgrading the connection from standard HTTP to the bidirectional WebSocket protocol (ws:// or wss://).

Test 8: Malicious Obfuscation (Obfuscated JavaScript)

The script uses a large number of variables, each holding a small fragment of a string encoded with hexadecimal (\x50\x47...) or Unicode (\u0046\u007a...) escape sequences. This makes the text unreadable to a human or a network security scanner.

All fragments are concatenated into a single, massive obfuscated string. A function is defined to call atob() to Base64 decode it. The final, decoded content is then executed directly into the DOM, triggering a malicious file drop and active payload execution.

View Obfuscation Logic
var MoV0EGAe = function(s) { return atob(s); }; // Variables containing hex/unicode fragments of the Base64 script var iouK_nAn = nY7MLAlg + z1rrdnSo + IouEedIh + hvp3Fatp + aFFXCLEi + eqaThGpC; // Payload executes immediately upon decoding document.write('<script>' + MoV0EGAe(iouK_nAn) + '</script>');

Phishing Defense

These tests check whether your security stack blocks known phishing test URLs and whether a credential-harvesting page rendered locally in the browser (a common SWG bypass) is detected. No credentials are ever transmitted — the form is an inert training mock.

Attackers increasingly reassemble phishing pages client-side so the malicious HTML never crosses the wire intact. This renders a benign mock of a corporate login page entirely in your browser. If your endpoint/enterprise browser flags it, your controls inspect the rendered DOM — not just network traffic.

Test 11: Malicious-Site Category Blocking

Attempts to reach a set of safe, industry-standard test endpoints (AMTSO & Palo Alto URL-filtering test pages). These domains are recognized by reputable filtering engines as "should-be-blocked" categories. A blocked request is a pass; a successful load is a bypass.

Web DLP / Data Exfiltration

Data Loss Prevention controls should stop sensitive data from leaving the browser. These tests attempt to exfiltrate synthetic, non-real canary data (a documented Visa test card number, a fake SSN pattern, and a unique canary token) over three common channels. If the data leaves un-redacted, your web DLP has a gap.

Test 12: Sensitive-Data Exfiltration Channels

Sends synthetic canary data via (a) an HTTP form-style POST, (b) a fetch() JSON body, and (c) a URL query-string beacon. All payloads use universally-recognized test values — no real PII is used. Watch whether your DLP/SWG redacts, blocks, or alerts on the transfer.
